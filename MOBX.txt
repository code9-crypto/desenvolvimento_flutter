CRIANDO AÇÕES E ESTADOS

TODO ESTADO É UM OBSERVABLE
Ex.: Observable count = Observable(0) //OBS.: assim que é declarado  um estado e no seu construtor deve ser passado um valor inicial
Observable discount = Observable(0)

ACESSANDO O VALOR DE UM ESTADO E RETORNANDO-O(normalmente por meio de um getter)
int get retonaValorCount => count.value; //este count.value é a forma que acessamos o valor do estado
int get retornValorDiscount => discount.value;

CRIANDO UMA AÇÃO
late Action acao;

CRIANDO A FUNÇÃO QUE SERÁ USADA POR MEIO DA AÇÃO
OBS.: aqui na função é possível chamar outra função a fim de que sejam chamadas duas funções numa mesma ação. Contudo, como são funções diferentes
então deverá ter outro estado diferente; com isso não é necessário criar outra ação, já que a mesma ação chamará duas funções diferentes
void incrementar(){
    count.value++;
    decrementar(); //eu chamo a outra função dentro da função que está vinculada com a ação
}

void decrementar(){
    discount.value--;
} 

CRIANDO O CONSTRUTOR QUE VINCULARÁ A AÇÃO COM A FUNÇÃO
Construtor(){
    acao = Action(incrementar);
}

USANDO NOTAÇÕES PARA TORNAR O CÓDIGO MAIS LIMPO
OBS.: essas notações pode criar: estados(observables), ações(actions) e gatilhos(computed)

tornando uma variavel ser um observavel / estado
@observable
int count = 0;
@observable
int discount = 0;

tornando uma função ser uma ação
@action
void increment(){
    count++;
}

OU

@action
void setCount(valor) => count++;

este(sempre será um get) retorna um valor quando um ou mais valores(observables/estados) combinados atendem a determinado critério
OBS.: esta notação é o retorno dos valores dos estados( ou o retorno da combinação dos valores )
@computed
bool get isFormValid => count > 10 && discount == -10 -> neste o retorno será um valor true ou false
IMPORTANTE: todos os @computed devem ser do tipo get, caso contrário não irá funcionar
OBS: quando no observer tiver apenas observando um valor não é necessário gerar um @computed, pode deixar observando apenas o valor estado(observable)
O @computed é mais inteligente ser usado para quando houver a verificação de dois estados(observable) ao mesmo tempo

********************************************************************************************************************************************************
AUTORUN -> ele é executado toda vez mesmo que não haja modificação em algum observable
obs.: este comando é usado dentro do contrutor da classe ou dentro do método didChangeDependencies;
outro detalhe é que este( autorun ) é executado sempre mesmo que não haja alteração do estado

class Classe{
    Classe(){
        autorun((_) {
            print(count);
        })
    }

    @observable
    int count = 0;
}

OU 

NOTA: Este didChangeDependencies é usado dentro da classe com StatefulWidget
@override
void didChangeDependencies() {
super.didChangeDependencies();

autorun((_){
        "ação para executar"
    })
}


********************************************************************************************************************************************************
MÉTODO REACTION(usado dentro do método didChangeDependencies)
Este método recebe dois parâmetros:
1º uma função anônima que ficará monitorando algum estado
2º uma função anônima que fará a ação quando um estado for modificado
OBS.: esta reaction só será executada apenas quando um estado for alterado e este fica dentro do didChangeDependencies
DETALHE: uma parte que faz uma diferença é usar o ReactionDisposer a fim de fazer o despejo de recursos que não esteja utilizando para que não haja uma sobrecarga de memória
E para fazer o disposer será dentro do método dispose o qual fica no fim da classe, pois é quando tudo já foi usado

@override
void didChangeDependencies(){
    reaction(
        (_) => classe.estado -> aqui é a parte do monitoramento do estado
        (value){ -> aqui é a parte da execução depois que o estado for modificado
            "ação para executar"
        }
    )
}

usando o ReactionDisposer(normalmente dentro de um StatelessWidget ou StatefulWidget)

Ex.: aqui está sendo usado um exemplo com StatefulWidget

....
Class _NomeClasse extends State<NomeClasse>{
    final ReactionDisposer disposer;
    
    @override
    void didChangeDependencies(){
        disposer = reaction(
            (_) => classe.estado -> aqui é a parte do monitoramento do estado
            (value){ -> aqui é a parte da execução depois que o estado for modificado
                "ação para executar"
            }
        )
    }

    .....

    //Esse dispose faz o despejo dos recursos que não estão sendo usado para evitar uma sobrecarga do uso de hardware
    @override
    void dispose(){
        disposer;
        super.dispose();
    }
}
